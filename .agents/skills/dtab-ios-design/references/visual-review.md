# 视觉验收与交付检查表

依据：[设计系统](../../../../docs/dtab-os-v1/06-DESIGN-SYSTEM.md) 与 [实施任务](../../../../docs/dtab-os-v1/05-CODEX-TASKS.md)。视觉验收补充而不替代原 A/G 验收。

## 1. 确认输入

记录正在验证的 commit、实际 URL、客户端/浏览器版本、操作系统、CSS 视口、DPR、主题、字体与测试数据。使用仓库真正存在的运行命令，不杜撰 pnpm 脚本。

确认参照图是否为用户认可的当前版本。没有图就按 06 规范评审，结果标为“实现规范检查，视觉待确认”。不把以前对话未取得的图片当作已知参照。

测试使用无敏感信息的固定 fixture；冻结时间/随机种子/网络数据用于快照，但不得由此宣称生产服务正常。测试与演示数据不能进入真实用户默认桌面。

## 2. 页面矩阵

| 页面 | 常态 | 必测扩展状态 |
| --- | --- | --- |
| Home | 预设图标、组件与 Dock | 空桌面、编辑、长名称、图标失败、第二页、复杂壁纸 |
| 添加 | 网址/组件/文件夹选择 | 字段错误、图标选择、保存失败、窄屏输入法 |
| 商店 | 推荐、列表与详情 | 空分类、加载、离线、不可用内容、已获取/已添加 |
| 相册 | 照片列表、相簿、查看器 | 空、上传中/失败、多选、无权访问、删除失败 |
| 设置 | 分组与账号 | 游客、登录、同步冲突、离线、恢复预设确认 |

常态覆盖 390×844、820×1180、1440×900，明暗各一套。可分阶段实现；没做到的页面标 not-run，不预先填写全矩阵通过。补测 320px、200% 缩放、减少动效/透明与强制颜色。

## 3. 每次截图检查

- 页面层级、标题、留白和视觉焦点是否正确；所有图标、控件是否共享同一 token。
- Dock/Sheet/键盘是否遮住最后一行或提交按钮；背景图有没有让标签不可读。
- 组件、照片与商品封面比例是否正确；长中文、空状态、错误文案是否完整。
- 表面是否克制：没有满屏玻璃、过多大圆角嵌套、每卡片折射或持续追光。
- 是否保留真实状态：没有假订单成功、虚假评价、未经验证的云相册成功界面。

截图生成后实际查看图像，修复明显偏差后重拍。只把文件写出来或读 DOM 不等于视觉检查。

## 4. 截图之外的交互

用鼠标、键盘和触摸模拟分别检查打开、返回、Esc、Tab、移动、排序和取消。动画在半途取消/连续触发不应卡住；动态效果减少后仍有明确反馈。

刷新和深链可用；焦点返回正确；图片失败可重试；数据写入失败可恢复。权限、跨账号、数据迁移与缓存另按 04-AUDIT 的 gates 测试，不能由视觉截图代替。

真实设备缺失明确说明。自动化 WebKit 不等于已在 iPhone/iPad 上验收，动画顺滑必须记录设备与观测，不用静态图证明。

## 5. 快照与报告

首次确认的浏览器截图才可作为视觉回归基线。出现差异先定位原因，不能自动全部更新快照；合法设计变更附原因与前后图。

大截图按仓库约定作为测试产物保存；不默认提交个人照片或大体积二进制。报告引用真实存在的路径，避免失效图片 ID。
