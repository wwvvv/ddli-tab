# DTab Makers Native — 产品与功能模块 v0.2

日期：2026-09-18。状态：基于用户授权调整的产品草案；未实现、未部署、未进行逐项产品验收。

## 1. 决策与定位

用户先要求放弃旧代码、基于 Makers 官方 Skill 从零开发，随后明确「网站功能模块也可以围绕着 Makers 调整」。因此，不再将旧版 Store/Gallery 等模块原样复刻作为前提。本文件优先于旧 PRD 和 v0.1 中关于固定模块、路由与开发顺序的描述；技术安全与真实验收要求不变。

定位建议：**以个人桌面为入口，将常用网站、轻量工具、AI 助手和个人文件放在一起的在线工作空间。** 保留 DTab 的统一入口、iOS/iPadOS 风格和统一账号，不变成 Makers 控制台的复制品，也不变成只有聊天框的网站。

Makers 用于选择合适的实现路径，而不是决定用户必须学习的平台术语。用户看到「应用、助手、文件、任务」，不需要理解 Functions、Blob、Agents 或 API Key。

## 2. 新信息架构

| 模块 | 路径 / 入口 | 首版交付边界 | 与旧版的关系 |
| --- | --- | --- | --- |
| 桌面 | `/` | 快捷方式、单层文件夹、Dock、少量组件、最近使用；支持手机/平板/桌面 | 保留身份与入口，减少复杂个性化引擎 |
| 应用库 | `/apps`、`/app/:appId` | 官方工具与 AI 操作入口；打开、添加到桌面、移除桌面入口 | 取代商店的电商化展示，不做第三方市场 |
| AI 助手 | `/assistant` | 文本问答、摘要、改写、翻译共用一套输入、历史和结果界面 | 提升为核心能力，不拆成多套聊天应用 |
| 文件 | `/files`、`/files/:assetId` | 私有上传、类型筛选、预览、下载、删除、AI 结果归档 | 原相册收敛为文件中的图片视图 |
| 设置 | `/settings`、`/settings/account` | 登录、资料、外观、同步与备份、安全、用量与数据管理 | 合并账号与权益信息，不新设独立用户中心 |
| 任务记录 | 共享面板，可有 `/activity` 深链接 | 显示真实执行状态、已保存结果、错误及取消请求 | 新增共享能力，不是自动化编排器 |
| 管理 | `/admin` | 官方应用可见性、版本化预设、动作开关、用户状态、审计 | 只做业务管理，不重造云控制台 |

默认 Dock 建议为「应用库、AI 助手、文件、设置」。尚未完成的能力不展示可点击假入口；可用性由实际运行验证决定。任务通过状态入口打开，不强制占一个 Dock 位置。

新应用从零起步，不创建 `/store` 与 `/gallery` 的第二套实现。以后确需兼容旧域名访问时再单独验证重定向，不在本轮改动生产路径。

## 3. 模块设计

### 3.1 桌面：常用入口，而非重型窗口系统

保留用户添加网址、改名称/图标、移动、分组、Dock 和基本组件。搜索优先检索本人快捷方式及官方应用名称，不等同于全网搜索或云端文件全文搜索。天气等依赖外部服务的组件不冒充平台内置功能。

游客可使用本地桌面及本地工具；登录后的云同步需通过账号隔离与冲突验收。多端更新保存历史快照，发生冲突时保留两版并让用户选择，不承诺首版自动无损合并。预设采用少量官方版本，新版本不自动覆盖用户布局。

不做任意多窗口、窗口平铺引擎、桌面插件市场、复杂主题编辑器、AI 自主改动用户桌面。提供键盘操作与触摸操作，减少动效/透明度设置仍有效。

### 3.2 应用库：统一入口，不为每个工具建一套系统

首批建议一个纯浏览器图片压缩工具，加上 AI 助手中的摘要、改写、翻译操作入口。图片压缩默认本地处理，只有用户主动保存到文件空间才上传。无需模型的操作不调用模型，不因为显示在 AI 平台就消耗 AI 积分。

应用库的主操作为「打开 / 添加到桌面」。桌面放置、可访问权益、代码加载是三件事，不以虚假的安装进度混淆它们。分类按实际内容提供，不用空分类凑齐游戏/主题/组件商店。

执行方式按操作定义：client（浏览器）、cloud（普通函数）、agent（Agent Runtime）。外部独立受管应用保留后续接入契约，不纳入首版交付。

官方注册表在源码中声明 appId、actionId、允许的输入类型、输出类型、所需权限及执行入口。后台只控制已审核注册项的展示与配置；不能录入任意 JS URL、工具代码或未经审核的后端地址。所有应用共用身份、文件引用和任务记录。

### 3.3 AI 助手：一套工作区，多种明确操作

首版使用一个经过实测的模型接入，普通用户优先选择「摘要 / 改写 / 翻译」等任务，不面对供应商密钥和几十个模型名称。模型与动作映射由服务端配置，不把临时免费模型当作永久成本假设。

第一条文件链路只接入有大小、字符数及编码限制的 TXT / Markdown 文本。图片可在文件模块预览，不因此自动获得视觉理解能力；PDF、Office、OCR、音视频和长文件解析后置，分别验证解析器、运行预算及模型支持。

单次模型调用可以使用普通函数；确需会话记忆、工具调用或沙箱时才引入一个合适的 Makers Agent 路线。不安装所有 Agent SDK，也不为了使用 Agents 把图片压缩等确定性操作变成多轮智能体。

用户显式选中文本或文件后才发送给模型。模型不能任意浏览整个文件空间，文件与网页内容按不可信输入处理。删除、外发、覆盖原文件等副作用不由模型文本直接授权；首版 AI 只读选中输入并创建新结果。

### 3.4 文件：围绕输入与产物，不做无限网盘

首版重点是 TXT / Markdown 与常用静态图片。文件内容和结构化元数据分别存储，通过 assetId、ownerId、来源及可选 runId 关联。列表使用分页和类型筛选；图片视图满足基础相册浏览，不再建设独立相簿/社交图库。

支持上传、预览、下载、删除和 AI 结果保存。原文件默认不覆盖，输出另存为新文件。AI 成功但保存失败时明确显示「已生成，云端保存失败」，保留当前结果供下载或重试保存，不能将其显示为完整成功。

文件默认私有。浏览器提供的 userId、路径或 Blob URL 不作为权限凭证；所有读、写、列表、下载和 AI 引用都由服务端验证归属。上传类型、实际内容、大小、配额和过期未完成对象必须验证。Markdown 渲染禁用原始 HTML 或严格净化，不渲染可执行用户内容。

不承诺无限容量、任意超大文件、公开分享链、全盘语义检索、协同编辑、视频转码或跨用户文件复用。配额是待配置的产品参数，不将官方免费额度写成永久赠送量。

### 3.5 任务记录：可追踪，不等于持久后台执行

各应用共用 runId 和状态契约：created、running、succeeded、failed、cancel_requested、cancelled、unknown。只展示已知状态；没有可测量总量时显示步骤/运行中，不编造百分比。

Agent 的会话标识、DTab 用户、runId、输入引用和输出引用需要服务端绑定。平台 traces 是开发排障数据，用户任务记录是 DTab 自己实现的经授权视图；不暴露密钥、内部工具参数、其他用户内容或模型隐藏推理。

停止操作先记录取消请求，收到确认才显示已取消。连接断开或函数超时不能推断上游必然停止或完全未计费；状态不明时显示 unknown，先检查与原请求的关联信息，不自动重发付费请求。

首版不承诺关闭浏览器后继续工作、不承诺后台队列或自动恢复。定时任务、跨小时流程、可靠重试和通知，必须另行验证 Makers 的相应运行契约、配额、持久化与恢复机制后再开放；控制台模板标签或一条任务 JSON 不是这种能力的证明。

### 3.6 设置与后台：精简但保留控制

账号、跨设备同步、数据导出、安全与用量集中在设置。后台先提供应用开关、官方动作配置、预设发布、用户禁用和必要审计；域名、部署、供应商密钥及平台 API Token 继续使用 Makers 的授权配置流程，不做成普通业务表单。

暂不建设复杂经营报表、创作者系统、分佣、排行榜、团队空间或组织权限体系。使用量展示区分真实上游 usage、应用估算、用户积分和平台账单，不互相冒充。

## 4. 首版验收场景

目标不是一次铺满全部应用，而是打通一条有用路径：

**从桌面打开 AI 助手 → 选中本人已上传的 TXT/Markdown → 摘要/改写/翻译 → 查看真实运行状态 → 将结果另存为私有文件 → 从文件模块再次打开或下载。**

同时保留不依赖云端 AI 的可用路径：游客打开桌面 → 添加常用网站 → 使用本地图片压缩 → 下载结果。

以上均为待实现的验收场景，不是已经运行成功的描述。先完成内部验证版；公开 AI 开放还需运行预算、滥用控制与实际资金授权，真实收费另过商业门槛。

## 5. 保留、合并和后置

保留：统一入口、账号、桌面交互、快捷方式、文件归属、基本个性化、一个会员与积分包的简单商业方向。

合并：相册并入文件；商店调整为官方应用库；多个 AI 文本工具共用 AI 助手；任务状态、文件产物、账号与权益由平台统一管理。

后置：任意第三方应用上传与市场、复杂多窗口、主题编辑器、独立大型相册、团队协作、向量知识库、自动爬取、用户自建工作流、定时自动化、重型视频处理、大型独立应用集成。后置不是永远取消，也不通过偷偷增加外部基础设施解决。

## 6. 商业与能力边界

保留「免费使用 + 一个 DTab 会员 + 积分包」，月付/年付为同一等级。每日积分重置不累计、不强制签到；购买积分不随每日重置或会员到期清零。会员内的普通低成本工具不再扣积分，明确按次成本的操作才进入积分结算。

本轮不批准价格、赠送量或换算比。实收、充值、退款和并发扣减仍须通过既定门槛；不将一个 Blob 计数器包装成账户余额。没有结算能力时不展示可用支付按钮，更不以「无限免费 AI」绕过成本问题。

Makers 原生不等于所有截图能力都已开通，也不等于可以无需开发交付上述模块。该方案减少独立系统数量，但 DTab 的身份、归属、任务状态、产品 UI 和安全结算仍是应用工程。
