# DTab OS V1 — 设计系统与 UI 规范

版本：1.0 · 2026-09-16 · 状态：实施规范，尚无已验收的界面截图

关联：[PRD](01-PRD.md) · [架构](02-ARCHITECTURE.md) · [迁移](03-MIGRATION.md) · [模型分工](07-MODEL-ROUTING.md) · [设计 Skill](../../.agents/skills/dtab-ios-design/SKILL.md)

## 1. 设计定位与优先级

DTab 是 iOS/iPadOS 交互取向的 WebOS：主屏幕、图标、文件夹、组件、Dock 和独立应用形成一致体验。不是把所有页面改成透明卡片，也不是复刻 Apple 品牌或某台设备的系统截图。

优先级：已确认的产品/安全要求 > 本文 DTab 规范 > 经用户确认的视觉稿 > 外部参考。视觉稿可以调整 token，但不能悄悄删除可访问性、权限状态或产品功能；遇到实质冲突记录设计决策。Admin 保持高效率后台，不做手机主屏幕。

本文尺寸、色彩、时长都是 DTab V1 的起始设计值，不是 Apple 的官方像素参数。首轮真实渲染评审后可统一调整；禁止各页面自行重新定义同一控件。iOS 26 命名的外部项目是参考版本，不代表项目必须追随每次 iOS 发布改版。

## 2. 五个界面的视觉职责

| 界面 | 组成 | 不应该出现 |
| --- | --- | --- |
| 主屏幕 | 管理员预设的背景、网址/App 图标、组件、单层文件夹、分页、Dock | 巨型欢迎横幅、推广导航墙、Windows 任务栏、多窗口系统 |
| 添加 | 网址/组件/文件夹三个入口；图标来源；目标位置；更多内容去商店 | 多级平台中心、未上线模块、只允许拖拽的操作 |
| 商店 | 推荐与真实内容分类、详情、获取/打开/应用/添加等明确动作 | 用户投稿、虚假评分销量、商品全部强制毛玻璃 |
| 相册 | 照片/相簿、上传状态、连续浏览、查看器和权限反馈 | 用演示照片冒充用户内容、私有链路未通过却宣称可用 |
| 设置 | 顶部账号、桌面与 Dock、外观、同步/备份、安全、关于 | 在普通用户主导航重复造一个用户中心 |

初始 Dock 包含商店、相册、设置，但以已发布预设的数据为准。新功能不自动插入老用户桌面。主屏幕时钟、日期和搜索可由预设/设置控制；不要硬编码默认网址清单。

## 3. 设计 token

实现时统一放入自己的 token 层，由 Tailwind/组件消费；本次只是 Markdown 规范，不新增生产 CSS 依赖。全部颜色采用语义名，主题可替换，不在业务组件散落硬编码。

### 3.1 颜色

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| --dtab-bg | #F5F6FA | #0E1118 | 应用页面底色 |
| --dtab-surface | #FFFFFF | #181E29 | 表单、列表、商店内容卡 |
| --dtab-surface-secondary | #EBEEF5 | #242D3B | 分组和次级容器 |
| --dtab-text | #171B26 | #F1F4FA | 正文 |
| --dtab-text-secondary | #515A6B | #AEB9CC | 说明文字，不使用整组 opacity 降低对比 |
| --dtab-accent | #245AE8 | #9CC0FF | 起始强调色，可统一改为品牌色 |
| --dtab-on-accent | #FFFFFF | #101827 | 强调按钮的文字 |
| --dtab-danger | #B42318 | #FFB4A8 | 错误和危险操作，必须同时有文字/图标 |
| --dtab-line | #DCE1EA | #333D50 | 装饰性分隔线，不单独承担控件可辨识性 |
| --dtab-control-border | #737F93 | #8090A8 | 必要的输入/控件边界 |

桌面图标标签不能只靠阴影适应所有壁纸。背景复杂时提供实色标签底或局部遮罩；无法保证可读时优先提高背景不透明度。透明合成后的实际对比需要在真实页面检查，不因为原 token 合格就认定玻璃文字也合格。

### 3.2 字体、间距与圆角

字体采用 `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` 和设备中文回退。禁止下载或提交 SF Pro、SF Symbols 字体包；中文不能套用英文标题的过度负字距。主体字号基于 rem，不禁用用户缩放。

| 类别 | DTab V1 起始值 |
| --- | --- |
| 页面标题 | 2rem / 1.2，600–700；移动端可降到 1.75rem |
| 分组标题 | 1.125rem / 1.4，600 |
| 正文/输入 | 1rem / 1.5，400–500 |
| 说明/图标标签 | 0.8125–0.875rem / 1.4；长名称最多两行并可查看全名 |
| 间距阶梯 | 4、8、12、16、20、24、32、40、48 CSS px |
| 圆角 | 控件 12，卡片 20，组件 24，Dock/Sheet 28 CSS px |
| 图标圆角 | 随图标尺寸约 24%，统一遮罩；不把 border-radius 宣称为精确 squircle |
| 点击区域 | 至少 44×44 CSS px；图形小于点击区域时用内边距实现 |

不要设置固定文本容器高度后裁掉放大文字。相册缩略图和产品封面可以固定比例；表单、错误信息与说明文字按内容增长。

### 3.3 图标系统

应用图标与网址快捷方式共享尺寸、名称和焦点语言；身份仍由 appId/URL 决定。上传图标属于个人覆盖，不改变真实应用发布者。内置图标、favicon、个人资产和 emoji 必须经 IconRef 渲染，不注入任意 HTML。

移动端图标起始边长 60px，平板 64px，桌面 72px；在各断点统一调整。透明用户图标置于可控底板，裁剪前有预览；失败时用名称首字/通用图标降级。用户 SVG V1 禁用，不能为了视觉效果放宽既有文件策略。

官方系统图标使用原创资源或已确认授权的图形。商店封面、桌面图标和菜单用小线性图标不是同一资产尺寸，不相互放大替代。文案“商店、相册、设置”固定，不恢复成多个中心。

## 4. 主屏幕布局与响应式

标准网格是 V1 首选；Shortcut 为 1×1，Widget 声明 2×2、4×2、4×4。尺寸是布局单元，不表示 CSS 正方形像素。坐标引擎与视觉尺寸分离，沿用架构中的 Entity/Placement 模型。

390px 视口先试 4 列；820px 先试 6 列；1440px 使用居中容器和 8–10 列，内容最大宽度起始 1120px。列数最终由可用宽度、最小点击区域和字体缩放决定，不拉伸整张移动端截图。320px/200% 缩放时允许降列；过宽组件使用声明的紧凑变体或单行满宽容器，不裁切内部按钮。

手机左右留白起始 16px、列间距 12px；平板/桌面留白起始 24/32px、间距 16/20px。每个图标预留名称区，网格行高必须容纳两行标签。动态 viewport 使用 100dvh 和 100vh 回退；安全区使用 env(safe-area-inset-*)。

底部为 Dock、分页提示和安全区留出实际占位，最后一行不得被遮挡。输入法弹出时优先保证输入框/提交按钮可见，Dock 可暂时让位，不覆盖表单。浏览器缩放或旋转不能自动覆盖用户另一断点的持久化布局。

页面是高交互 Web，不拦截操作系统边缘返回手势，不默认禁用滚动/浏览器缩放。触摸拖动只在编辑模式/拖动区域启用；表单、商店和相册维持原生纵向滚动。

## 5. 材质与层级

采用实色优先、CSS 玻璃渐进增强。Apple WWDC25 的材质说明强调导航层与内容层分离，并提醒避免玻璃叠玻璃；DTab 参考这个组织原则，而不声称浏览器 CSS 等同原生 Liquid Glass。[D01]

| 区域 | 默认处理 |
| --- | --- |
| Dock、上下文菜单、Folder Panel、小型工具栏 | 单层半透明 + 边界 + 轻阴影，可启用 backdrop-filter |
| 添加 Sheet 外壳 | 可轻玻璃；内部表单区域优先实色/足够不透明 |
| 相册/商店内容、设置分组、Admin 表格 | 实色或清晰内容底；不逐卡片折射 |
| 照片网格、App 图标、正文列表 | 无常驻毛玻璃滤镜 |

建议标准玻璃起始为浅色 88% 白/深色 90% 深底，blur 16px、saturate 120%；依据真实壁纸合成结果调整。它是视觉提案，不是自动达到对比要求的保证。

默认不安装 liquid-glass-react 或另一套玻璃库；不增加 GSAP/WebGL。无 backdrop-filter、减少透明、强制颜色或低性能模式下，改用实色、清晰边框。减少透明在设置中提供显式开关，不能依赖所有浏览器都支持同一个媒体查询。

V1 禁止背景持续折射、鼠标追光、所有图标悬浮放大和多层滤镜嵌套。任何试验效果必须独立开关、测真实设备后再决定，不能以外部 README 的兼容表代替测试。

建议语义层级：背景 0、桌面内容 10、Dock 20、应用 30、Folder 40、Sheet/菜单 50、确认框 60、Toast 70。实际实现集中定义 portal 层级与遮挡规则；z-index 本身不构成权限或模态焦点管理。

## 6. 组件合同

### Home / Dock

点击/Enter 打开，右键或显式菜单操作，长按只作为补充入口。编辑模式有“添加/完成”，移除按钮与打开按钮不嵌套；危险操作区分“移除入口、卸载应用、删除数据”。连续抖动不是必需；减少动效下采用轮廓和操作标记。

Dock 固定应用数据来自预设/用户 pin，不写死 JSX；支持排序、移除、再次添加。V1 不做最近使用分区。默认不持续放大；active/pressed/focus 状态足够。缩小屏幕时不要把按钮压到 44px 以下。

### Folder / Widget

Folder 打开为有标题和关闭操作的面板；按 Esc 或外部点击可关闭，关闭后焦点回到原图标。禁止文件夹嵌套。拖入/移出与菜单移动使用同一命令层，不单独维护一份 folderChildren。

Widget 可配置尺寸和内容，但必须有 loading/ready/empty/offline/error/unsupported 状态。旧组件未迁移时保留配置并明确不可用，不用静态假数据取代真实结果。

### Sheet / 菜单 / 表单

窄屏底部 Sheet；宽屏锚定 Popover 或居中对话框。每个模态有可访问名称、初始焦点、焦点约束、退出路径与焦点恢复；参照 WAI-ARIA 对话框模式。[D02] 表单失效展示具体字段原因，不只给红框。保存中防重复提交，失败保留输入；有未保存改动时关闭需要保护。

内部选项切换使用适当的 tabs/segmented control；跳到另一页面使用真实链接，不能把所有导航都做成 div onclick。触摸长按与菜单不可取代键盘操作。

### Store

推荐内容可用编辑式大封面，但第一屏保留搜索/分类入口。分类数量以真实内容为准；每行或卡片有清晰主操作。系统应用“打开”，组件“添加”，主题“应用”，网址“添加到桌面”。“获取”不等于购买，付费未开放时隐藏扣款动作。

### Gallery

照片是视觉主体。初版优先使用有序等宽网格，时间分组；数据量大时虚拟化并保留滚动位置。缩略图支持裁切预览，查看器提供适合窗口/原始比例切换；不拉伸原图。选择模式显示数量与批量动作，不靠 hover 才可操作。

上传区区分处理中、上传中、登记中、成功、失败；只对真实成功给成功反馈。私有链路 gate 未过时显示未开放，不用样例照冒充个人相册。

### Settings / Admin

手机设置分组列表，桌面可用侧栏+详情。顶部账号卡、每组标题、说明和明确动作；开关状态落到真实服务/本地事务。同步与上传限额可见，不为“简洁”隐去。

Admin 可共享字体/表单/颜色，但保留表格、筛选、分页和审计效率。官方预设编辑模式持续显示独立提示，不让管理员误改个人桌面或泄露私人资产。

## 7. 动效与可访问性

简单反馈用 CSS transform/opacity：按压起始 80–120ms，悬浮/淡入 120–180ms。App/Folder/Sheet 切换目标体验约 220–360ms，可中断；必要时使用 Motion spring，不把时长当作弹簧绝对结束时间。起始 spring 可从 stiffness 360、damping 34、mass 1 调试，这不是 Apple 参数。

App 打开若 origin 图标可用，可做轻微共享元素过渡；直接刷新深链时不伪造动画起点。异步加载、失败、返回和取消都必须可响应，不等动画结束才处理输入。无必要的大幅位移、parallax、反复弹跳不使用。

系统 prefers-reduced-motion 或 DTab 减少动态效果任一启用时，禁用位移/弹簧/抖动/自动轮播，用即时变化或短淡入。强制颜色保留系统色和边界；不对全页设置 forced-color-adjust:none。仅在拖动容器有必要时限制 touch-action，不禁用全站缩放。

DTab 验收目标：普通文字对比至少 4.5:1，必要非文本控件边界/图形至少 3:1，44px 点击区域、可见 focus、200% 缩放与完整键盘路径。对比目标参照 WCAG，44px 是本项目交互要求，不能据此单独宣称整站通过 WCAG。[D03]

## 8. 设计交付与视觉验收

先定义 token 和 UI 合同，再做 Home/Dock/添加的最小设计样例；用户明确要求设计稿时才生成图片。当前仓库没有新确认的 OS 设计图，不从其他对话的模糊图片 ID 推断目标。

有设计图时记录来源、版本、视口与确认状态，按同视口真实页面截图对比；没有时按本规范做首版浏览器样例，标记“待视觉确认”，不停止可执行的本地开发。

至少验证 Home、添加、商店、相册、设置在 390×844、820×1180、1440×900 三种 CSS 视口的明暗主题。补测复杂壁纸、长中文、空/加载/错误/离线、Folder、编辑模式、减少动效/透明、200% 缩放。详细检查表见 Skill 的 visual-review reference。

报告分别列出视觉偏差与功能/安全缺陷。截图漂亮不代替 A/G gates；截图只能检验静态状态，拖动、动画中断、焦点、上传与跨账号必须交互测试。禁止直接更新快照基线掩盖失败。
