# DTab OS V1 — 桌面端模型选择、任务分工与审查规则

版本：1.1 · 更新日期：2026-09-16

关联：[任务顺序](05-CODEX-TASKS.md) · [设计系统](06-DESIGN-SYSTEM.md) · [审查门槛](04-AUDIT.md)

## 1. 本次更新与生效边界

用户使用 ChatGPT 桌面版，本文件以桌面模型选择器为主，不再要求用户安装或改用 Codex CLI。按已确认的项目分工，Astra 负责规划/审查，Sol 负责核心与集成，Terra 负责契约明确后的页面实现。

本次更新的是仓库规则，不是用户电脑上的活动模型配置。没有修改全局或项目 config.toml、创建 .codex/agents 配置、调整审批权限或启动并行任务。读取 AGENTS.md/Skill 不等于当前主会话已经换模型。

官方已经文档化子 agent 的模型与推理力度选择，因此也不能再笼统声称“Codex 只能手工选择模型、不支持分模型委派”。必须区分：主会话选择、启动不同模型的子 agent、仓库文字规则三件事。支持的机制见第 4 节；用户本机是否实际采用仍需验证。[M01][M02]

## 3. DTab 默认分工

以下是项目分工建议，不是项目实测的模型性能排名。推理档位以该桌面客户端实际提供的选项为准；不默认开启 Max/Ultra，不把更高档位等同于一定正确。

| 角色 | 默认模型 | 目标档位 | 当前可用证据与替代方式 | 工作边界 |
| --- | --- | --- | --- | --- |
| PLANNER 规划 | GPT-6 Astra | 中或更高的实际可选档位 | 截图仅见轻度；可用轻度完成小范围计划并记录实际档位 | 阶段拆分、需求变更影响；不重新推翻已确认 PRD |
| CORE 核心/集成 | GPT-5.6 Sol | 优先高，须在本机确认 | 截图见中；高未确认时用中做基线/已界定任务，复杂事项单独审查 | M0/M1、共享契约、布局引擎、迁移、Auth/RLS、同步、私有媒体、集成 |
| UI 页面实现 | GPT-5.6 Terra | 中 | 截图可见；实际任务开始前核对选择器 | 既定设计 token/接口后的商店、相册展示、设置、普通组件和局部测试 |
| REVIEW 阶段审查 | GPT-6 Astra | 中或更高；关键节点优先更深入的可选档位 | 目前仅见轻度；采用其他档位后补证据。只能用轻度时记录初审，必要时补独立 Sol 审查 | 跨模块、安全、迁移、设计一致性及上线材料，默认只读 |

复杂 UI、拖拽碰撞、共享动效/焦点或两轮仍无法定位的问题由 Sol 接手；Sol 中/高按本机实际可选项选择。Terra 不因承担“相册页面”就获得改媒体权限设计的职责。

本次将普通 UI 默认负责人从旧版规则的 Sol Medium 调整为 Terra 中。Sol 仍是升级处理与集成负责人。历史文档中的 ECONOMY 可选角色不再单独维护，与现在的 UI 页面执行角色合并。

Astra 临时不可用时用独立 Sol 会话审查，记录替代模型与实际档位；Terra 不可用时页面工作可由 Sol 中承担。不需要为了等一个未出现的档位暂停无依赖的基线检查，但真实越权、数据丢失、未满足发布 gate 必须阻止相关功能上线。

“GPT-5.6 Pro”不作为本项目确定可调用的 Codex ID；套餐或产品模式名称不能用来推导模型 ID。不要写不存在的名称到活动配置。

## 4. 桌面操作与真实分模型委派

### 4.1 当前主会话：由用户选择

在输入框下方打开模型/推理控制；当前截图也提供 `Ctrl+Shift+M` 入口。选择模型后再检查推理档位，发送下一条任务前确认底部状态。等待当前操作结束或正常中止后交接，不能假定菜单变化会追溯改变已经运行中的请求。[M01]

这份仓库提交不会替用户按快捷键，也不能宣称已经把当前 Terra 会话切成 Sol。用户不用为了此流程打开终端执行 `codex -m` 或 `/model`；这些属于其他客户端的操作方式。

### 4.2 子 agent：官方支持，但本机尚未实测

官方 Subagents 文档允许通过受支持的启动请求或自定义 agent 设置模型/推理力度；未指定时有继承/默认规则。当前文档也列出项目级 `.codex/agents/` 与 `model`、`model_reasoning_effort` 等设置。[M02] 这说明分模型委派有真实运行机制，而不是仅凭角色名称模拟。

不过，子 agent 用不同模型不等于主会话自己切换。AGENTS/Skill 可以给出委派指令，最终必须由本机实际存在的子 agent 工具执行；仅输出“Terra 已完成”没有独立线程/运行证据，不能算执行过委派。

本次不安装上述活动配置。M0 可检查现有工具支持；没有对应运行能力时使用分别选择模型的独立会话顺序交接，不要求伪造并行。要增加持久配置时先确认当前客户端 schema、已有设置和用户授权，不覆盖全局偏好、放宽审批或擅自切到 API-key 付费路径。

### 4.3 三个证据等级

- `picker-visible`：可见模型/档位选项。
- `selected-ui`：界面明确显示当前选择。
- `runtime-verified`：一次实际任务有可观测运行元数据支持，包括模型/档位及子线程（适用时）。

只能观察 UI 时就记录 UI，不要求凭空取得产品未暴露的内部元数据。截图目前达到前两类中的相应状态，不把它升级成第三类。未暴露的字段填 unknown。

## 5. 风险升级规则

普通页面在契约已稳定时交给 UI。出现以下任一变更转 CORE，由单一集成负责人接手：

- desktop schema、实体 ID、Dexie 升级、导入迁移/恢复和云同步协议。
- Service Worker、缓存、根路由切换、Auth/RLS、管理员授权、会话与用户隔离。
- 媒体读取/上传授权、删除一致性、配额、支付、SQL migration、部署/回滚。
- 共享设计 token、网格/碰撞规则、全局焦点/模态/动效、App Registry 或 lockfile。

商店卡片显示属于 UI；商品定价、订单、权益与远程代码入口属于 CORE。相册列表/查看器展示属于 UI；私有媒体、删除/恢复和跨用户权限属于 CORE。普通 CRUD 一旦涉及归属、鉴权或计费，不再按低风险任务处理。

同一问题连续两轮无可靠定位、修改范围扩散、出现跨账号异常或数据不一致，先停止扩大改动，保存最小复现与交接材料，再升级 CORE/REVIEW；不能继续猜测后以“高级模型保证安全”放行。

## 6. M0–M5 模型与任务分配

表中“目标高”均是未必已验证的配置目标；实际执行采用第 3 节的降级规则，记录实际档位。

| 阶段 | 默认主负责人 | Terra 中可以承担 | Astra 审查节点 |
| --- | --- | --- | --- |
| M0 | Sol：目标高，已见中可起步 | 默认不并行写入；明确范围的只读清点可后置 | 基线、依赖/平台证据、未知项和模型记录 |
| M1 | Sol：目标高 | token/契约确定后的孤立静态控件 | 新壳、旧 SW/路由、包管理迁移、设计系统样例 |
| M2 | Sol 核心 + Terra 展示 | Home/Dock/添加/文件夹的既定 UI、局部测试 | 布局数据、旧导入/回退、响应式与键盘操作 |
| M3 | Sol：目标高 | 设置/预设编辑器的展示层 | Auth/RLS、双设备、换账号、预设发布/恢复 |
| M4 | Sol 服务/集成 + Terra 页面 | 商店、相册查看器、设置与组件展示 | 私有媒体、删除、安装/权益、跨页面一致性 |
| M5 | Sol 集成 + Astra 审查 | 范围明确的展示修复与测试补充 | `/os` 切根路径之前，离线、扩展、回滚与全部发布 gates |
| M5-P | Sol：目标高 | 已定接口后的账单显示，不改计费逻辑 | 启用真实收费之前；验签、幂等、退款与权益 |

开发阶段未开始则从 M0 进入；本地已有实施提交时先核对当前阶段与报告，不为了采用新模型再次覆盖已完成代码。模型验证不替代原构建/数据库/浏览器基线。

## 7. 并行与文件所有权

M0/M1 默认一个可写负责人。M2 契约冻结后再按能力开 2–3 个范围明确的任务；暂不能证明独立工作区/实际子 agent 可用时顺序执行。每个任务记录基线 commit、允许/禁止修改路径、契约版本与验收命令。

CORE 独占 package/lockfile、共享 token、desktop schema、SQL migrations、Auth、SW、媒体授权、App Registry 和部署文件。Terra 页面任务只写自己的目录/测试；共用 token 需要调整时提交给 Sol 汇总，不能每页另建一套颜色/尺寸。

独立会话不天然等于独立 worktree；即使客户端具备 worktree 功能，也需检查具体任务实际在哪个目录/分支。多个写入者不得争用同一工作树；只读 reviewer 不创建提交或执行发布。无法落实文件所有权时取消并行，不以同时显示多个聊天窗口作隔离证明。

UI 任务使用 `.agents/skills/dtab-ios-design/SKILL.md` 与 06 设计规范；更换模型不改变 iOS/iPadOS 风格、官方商店、单域名或任何既定产品范围。

## 8. 审查、交接与报告

提交给 REVIEW 的最小材料：阶段/需求、base/head commit、变更文件、实际测试结果、未执行事项、截图路径与视口、待审问题、数据影响、回滚方式。不得附带凭据、私人相册或生产数据。

REVIEW 先检查正确性、权限、数据保护和范围，再审设计一致性与性能。输出具体文件/行号、严重程度、复现和修复建议；浏览器没运行就不声称视觉测试通过。独立会话审查减少上下文偏向，但不是正确性保证。

```text
阶段/任务：
建议角色、模型与目标档位：
实际客户端与版本（未观察为 unknown）：
实际 UI 模型名称 / 档位 / 证据等级：
实际 model_id / resolved effort（未暴露为 unknown）：
子 agent / 线程 / worktree（无则 none，未验证则 unknown）：
base/head commit 与允许修改路径：
完成内容：
验证：passed / failed / blocked / not-run
截图与交互证据：
升级/替代原因、风险与阻塞：
下一步与回滚：
```

任何模型都不能绕过原 A/G 验收、安全策略、生产授权或未提交改动保护。真实收费、部署切换、删除数据与购买资源仍按原批准边界执行。

## 9. M0 模型验证清单

本地实施者实际检查后生成 `implementation/M0-MODELS.md`，不要由远程文档提交预填本地测试通过。

| 检查 | 当前状态 | 后续要求 |
| --- | --- | --- |
| Sol 中、Astra 轻度、Terra 中显示 | picker-visible | 记录用户截图观察日期；不是完整模型列表 |
| Terra 中当前选中 | selected-ui | 仅代表截图时的选择，不推断现在所有任务 |
| Sol 高、Astra 中/更高档位 | unknown | 在用户模型/推理控件中实际核对，不猜枚举 |
| 三模型分别运行任务 | not-run | 各自做无写入的仓库阅读任务；区分 UI 观察与运行元数据 |
| 模型与档位在任务切换后是否保留 | not-run | 分任务检查，不假设全局继承 |
| 分模型子 agent / 并行隔离 | not-run | 工具确实可用时做只读小任务，检查独立结果及可见运行信息 |
| dtab-ios-design 实际发现与调用 | not-run | 查技能入口或显式调用，保留实际结果 |

模型检查只读即可，不需要新增 API key、修改付费配置或开很多并行任务。机器环境不足时记录 blocked，继续不依赖它的任务。
