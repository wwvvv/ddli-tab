# DTab OS V1 PRD

版本：1.1 · 2026-09-16 · 状态：可进入分阶段实施，未验收上线

关联：[技术架构](02-ARCHITECTURE.md) · [迁移方案](03-MIGRATION.md) · [审查记录](04-AUDIT.md) · [Codex 任务](05-CODEX-TASKS.md) · [简化收费方案](08-BILLING.md)

## 1. 产品定义与范围

DTab 是一个浏览器里的个人桌面：把网站快捷方式、官方应用、组件、照片和个性化外观放在同一套 iOS/iPadOS 风格的交互体系中。网址能力保留，但不再把产品做成传统导航站。

设计方向：主屏幕、规则网格、圆角图标、文件夹、Dock、组件、编辑模式、全屏/大面板应用切换。桌面浏览器、平板与手机共用产品模型。V1 不做自由拖拽多窗口、任务栏、开始菜单或 Android 式应用抽屉。

未来大型官方受管应用可以自定义域名、独立部署并在新窗口/标签页打开，统一接入 DTab 账号与权益，不要求移植其完整 UI。此项是后续集成边界，不将 Infinite Canvas、New API 或 SSO 实现加入当前 Core V1。

### 1.1 V1 必须交付

| 编号 | 模块 | 交付边界 |
| --- | --- | --- |
| P01 | 主屏幕 | 网页快捷方式、官方应用入口、组件、单层文件夹、分页与 Dock |
| P02 | 添加 | 添加网址/组件/文件夹；名称、图标、目标位置可编辑 |

| P05 | 设置 | 账号、桌面与 Dock、外观、同步与备份、我的内容、安全、关于 |
| P06 | 预设桌面 | 管理员可视化编辑、预览、版本化发布、回滚发布；新用户复制 |
| P07 | 管理后台 | 官方商品/网址/预设维护、用户状态、系统开关、审计日志 |

### 1.2 V1 不做

创作者中心、用户投稿作品、任意 ZIP/H5 执行、第三方应用沙箱、开发者收益/提现；聊天、复杂阅读器、AI 萌宠对话、重型游戏、视频转码、AI 自动创建应用；用户自定义存储、多套 Core 后端、VPS 生产运维；多人协同编辑。

保留后续扩展位置不等于实现这些功能。不可显示虚假安装量、虚假评分、假支付成功或不可用的“已上线”应用。

商业权益模型需要预留，但试运行默认关闭收款。正式收费必须通过支付验收门槛，具体支付渠道、币种、价格、税费和退款规则另行确认；此前聊天里的价格只属于建议，不是本 PRD 的确定值。

### 1.3 初期收费合同

唯一用户口径：**免费使用 + 一个 DTab 会员 + 积分包**。详细规则与 New API 验收见 [08-BILLING.md](08-BILLING.md)，替代早期多等级和单品买断设想。

- 基础桌面、网址、自定义布局与基础内容继续免费。会员解锁已列明的会员工具/高级功能；月付/年付是同一等级的期限选择。
- 普通已登录用户有少量每日积分，会员更多。每日重置、不累计、不要求签到；购买积分不参与每日清零、不因会员到期消失。
- 普通用户可单独购买积分使用可用 AI，不强制先买会员。大型 AI 应用基础工作区不默认要求会员；高级工作流等功能才可以是会员权益。
- 会员内的普通低成本工具不扣积分；有明确按次成本的 AI/第三方 API 操作才走积分。去水印的普通模式与智能修复可采用不同规则，不对整款应用一刀切收费。
- 初期不做 Max、每应用 VIP、普通工具单次购买、主题/图标/小工具单品买断、积分转账/提现或活动奖励第三钱包。
- 操作前明确“会员包含”或“使用/预计 N 积分”。首次使用购买积分及高成本操作有清晰提示；不在处理完成后突然加付费下载门槛，不默认自动充值。

具体积分数、售价和换算比例未定。New API 作为未来 AI 配额/实际扣费真源，DTab 不维护另一套 AI 余额。每日重置、跨池差额结算、并发、跨日任务和发放幂等未经实测不得开启真实收费。

## 2. 信息架构与页面

| 用户名称 | 正式目标路径 | 说明 |
| --- | --- | --- |
| 桌面 | `/` | 默认首页 |
| 商店 | `/store`、`/store/[slug]` | 唯一对外名称就是“商店” |
| 相册 | `/gallery`、`/gallery/albums/[id]` | 官方系统应用 |
| 设置 | `/settings` | 账号位于设置顶部，不另设显眼的用户中心 |
| 我的账号 | `/settings/account` | 登录、资料、会员/权益、订单、安全；积分能力交付后再显示 |
| 管理 | `/admin` | 正常高效率后台，不强行做成主屏幕 |
| 应用 | `/app/[appId]` | 只打开注册表内的官方应用 |

开发期先使用 `/os` 命名空间验证新壳；最终路径切换见迁移方案。路由变化必须兼容浏览器前进后退、刷新和深链接。V1 原生应用打开以全屏或大面板呈现，有明显返回桌面的操作；不依赖只有触摸设备才有的手势。

默认 Dock 由预设决定，首套预设包含“商店、相册、设置”。系统应用不可从平台卸载，但可从 Dock 移除；设置与商店必须仍可从系统菜单/搜索找到。未来加入聊天只更新新用户预设，对老用户提示可选添加，不自动占位。

## 3. P01 主屏幕与交互

### 3.1 桌面内容

- 快捷方式：指向 http/https 网址或官方 appId。未来文件目标先保留类型设计，不提供不可用入口。
- 组件：一个可配置实例；同一组件允许多个实例，各有独立设置。
- 文件夹：只容纳快捷方式，不支持文件夹套文件夹，V1 不把大型组件塞进文件夹。
- 放置记录：定义内容出现于哪一页、哪一格或 Dock；内容定义不随拖动被复制。

外部网址默认在新标签页打开；使用安全的 opener 隔离。不承诺所有网站能嵌入 DTab，遇到禁止嵌入的网站不绕过其限制。

### 3.2 网格与编辑

标准布局是 V1 主路径：快捷方式占 1×1，组件从 2×2、4×2、4×4 中声明可用尺寸。这是 DTab 自己的网格规范，不要求逐像素复制 Apple。

鼠标：右键/显式“编辑桌面”按钮进入编辑；触屏：空白处长按，并保留按钮入口。编辑状态出现“添加”和“完成”。键盘用户可通过可聚焦菜单完成添加、移动与删除，不能把拖拽作为唯一途径。

支持同页排序、移动到其他页、拖入文件夹和 Dock 排序。第一版跨页移动可以用菜单完成，再增强边缘悬停翻页。所有拖拽须有落点预览、取消操作与非法目标提示。

桌面端、平板、手机分别计算有效列数；同一内容集合可以有不同断点的布局记录。浏览器宽度变化不应不断写回覆盖其他设备布局。相同断点的布局变更才进入该断点的同步数据。

旧版自由坐标与横卡/大卡不能静默丢弃。先在迁移报告中保留、提供旧版备份/回退；新自由布局引擎列为 V1 后续增强，不将其和标准网格同时作为首个交付任务。

### 3.3 基础外观

背景、图标大小、文字显示、主题明暗、时钟/日期/搜索的显示由设置控制。主屏幕使用 DTab 自有设计 token 与图标；shadcn/ui 主要提供对话框、菜单和表单，不直接充当桌面视觉主题。

动效服从 prefers-reduced-motion；关闭动效后功能相同。减少透明效果时提供实色面板。交互目标建议至少 44 CSS px；键盘焦点可见，文本不依赖背景壁纸维持可读性。

## 4. P02/P09 添加与图标

统一“添加”面板只展示网址、组件、文件夹，底部可前往商店。已安装应用从“我的内容”或商店详情重新添加到桌面，不需要重新获取/安装；添加入口也不应触发收费。

### 4.1 添加网址

输入 URL、名称、图标、添加位置；无名称时可用域名作为可编辑默认值。只允许 http/https，拒绝 javascript/data/file 等可执行或本地协议和含用户名密码的 URL。

手动添加不能承诺总能抓到网页标题：跨域与站点限制下使用域名和候选 favicon；浏览器扩展在用户主动触发时可采集当前页面信息。V1 不引入任意 URL 的服务端抓取代理。

内网/NAS 网址可以作为用户本地快捷方式保存，但平台不得主动抓取私有 IP、localhost 或云元数据地址。重复网址提示已有位置，用户可选择创建另一处放置，不做破坏性自动去重。

### 4.2 图标

入口：自动获取、上传图标、我的图标。用户可为网址和文件夹上传图标；官方应用图标可做个人外观覆盖，但不改变 appId、权限或发布者标识。

第一版上传 PNG/JPEG/WebP；浏览器可先裁剪和缩小，但服务端仍校验文件签名、像素上限、实际格式和大小。任意 SVG 不以内联 HTML 加载；V1 用户 SVG 上传默认禁用，官方仓库中的审查过 SVG 可以使用。动态图标不列为首版承诺。

建议图标最终不超过 512×512、512 KiB，原始待处理文件上限由服务端配置且清晰提示。这些是起始产品限制，不是上游平台配额。

已登录用户图标保存到官方 ImgBed，并在 DTab 记录归属；游客可先使用 IndexedDB 本地图标，登录后逐项上传并转换引用。失败时保留本地引用，不能生成假的云端 assetId。

我的图标可复用、显示引用情况。删除仍被使用的图标时，需要先替换为默认图标或明确确认，不造成无提示的断链。

## 5. P03 商店

### 5.1 分类与行为

“推荐”是运营页面，不是商品类型。一级入口采用：推荐、应用、组件、主题、游戏、网址；内容不足时隐藏空分类，不为了凑数量上架失效内容。

| 对象 | 主操作 | 规则 |
| --- | --- | --- |
| 系统应用 | 打开 / 添加到 Dock | 标记内置，不重复安装 |
| 官方可选应用 | 获取 / 打开 / 移除 | 获取代表账户安装记录与资源激活，不是执行上传代码 |
| 组件 | 添加到桌面 | 已内置的组件不要求重新获取 |
| 主题 | 预览 / 应用 | 更改外观，不覆盖网址、文件夹、个人图标覆盖 |
| 游戏 | 获取 / 打开 | 逻辑上属于官方应用，用游戏分类展示 |
| 网址 | 添加到桌面 | 保存用户自己的快捷方式副本，不产生收费安装订单 |

GoTab 原组件逐项清点为“可复用/需替换服务/暂不可用”。只有完成实际验收的组件进入商店；原有免费、本地可用功能不突然收费。旧服务器依赖不可用时明确提示并保留配置，不伪造数据。

原资源库收敛到“商店 → 网址”，底层是独立 web_resources 数据，不和 Product 混为一张万能表。V1 官方维护，不接收用户投稿；用户添加私人网址始终允许。

应用可提供配套组件，例如相册的照片组件。安装记录和组件实例分开；删除桌面入口不等于卸载，卸载不等于立刻清除用户所有数据。

### 5.2 商品信息

标题、简述、官方发布者、图标/封面、截图、版本、兼容要求、内置标识及“免费/会员包含”状态；有积分操作时注明“部分处理使用积分”。没有真实评价就不显示星级；网络不可用时显示已缓存信息或离线状态，不展示假成功。

商店初期不售卖主题/图标/小工具单品，会员和积分包统一从账号/购买页成交。应用级访问策略和操作级计费策略分开：打开基础工作区不默认扣分，具体处理提交前才显示费用。未上线的会员/AI 能力不能作为已可用权益销售。

官方程序代码随 GitHub 审查、构建和部署发布。后台只能编辑文案、资源引用、上架状态、推荐和权益配置，不能填写任意 JS URL 作为应用入口。

## 6. P04 相册

产品名称使用“相册”；“无限相册”描述可连续浏览/组织的体验，不表示无上限字节存储或无条件永久保存。上传额度、文件类型、容量政策必须可见，不以隐藏限额误导用户。

首版支持 PNG/JPEG/WebP 照片；照片页按拍摄时间（可用且有效时）或上传时间排序，支持分页/虚拟化；相簿是业务集合，一张照片可进入多个相簿。收藏是用户关系，不靠修改 ImgBed 文件标签替代。

上传流程：选择文件 → 明确显示处理/上传/登记状态 → 成功后出现在列表。禁止将压缩副本悄悄冒充原图；大于当前安全上传上限时说明限制，用户可主动选择压缩副本，或等待大文件链路上线。

查看器支持上一张/下一张、缩放、收藏、加入相簿、下载原文件、删除。缩略图不支持或上游异常时有明确占位与重试，不自动批量请求超大原图造成流量放大。

删除行为分开：从相簿移除只删除集合关系；删除照片先撤销访问并进入可恢复状态，再由受控清理流程清除底层文件。云端删除失败必须保留待清理状态、重试与管理员提示，不能直接宣称物理删除完成。

私有性为发布门槛：登录用户只能访问自己的相册、媒体和缩略图；知道上游真实地址、复制 URL、退出登录或换账号后也不能绕过。ImgBed 的公开文件链接、随机图和来源防盗链都不能自动当作用户权限。实现要求见架构与审查记录。

视频、大文件分片、人物识别、地理聚类、共享相簿、批量转码不作为第一轮上线前提。原图/大文件上限取所有运行环节中最小的有效上限，实测通过后才能放开。

## 7. P05/P08 账号、同步与本地优先

游客可使用桌面、网址、基础组件、主题、导入导出与本地图标。云相册、跨设备同步、会员/积分购买与有成本的 AI 操作要求登录；登录不等于必须开会员。

用户中心整合进设置的账号区域；当前旧版本账号入口迁移时保留引导，不让两套 UI 并发控制同一同步写入。

本地编辑先形成持久化事务，界面即时反馈；写入失败明确提示未保存并撤销/恢复，不把内存变化误报为已保存。联网后同步，不要求每次拖动等待服务器。

登录时必须区分游客桌面与该账号云端桌面。已有云数据时由用户选择使用云端、导入本地或取消；不能用新设备默认桌面覆盖云端。账号切换隔离本地库、待发队列与媒体缓存。退出后停止旧账号同步、忽略在途响应并清理内存数据；保留本地副本须有用户明确选择与设备隐私提示。

同步状态：仅本地、同步中、已同步、离线待同步、需要处理冲突。数据变更不依赖客户端时钟排序。冲突时保留双方备份；整份选择的破坏范围必须说明。

IndexedDB 不等于离线启动。离线主屏幕需要 Service Worker 及已缓存代码。第一次从未访问的网站无法无网加载；未缓存的应用/远程网站/照片也不承诺离线可用。

导出内容包含桌面与可移植配置；不会把账号令牌、管理员身份、购买权益、积分凭据或整个云相册原图塞进 JSON。桌面重置绝不删除相册、订单、云端文件和账号。

## 8. P06 官方预设桌面

管理员在独立“预设编辑模式”中复用真实桌面编辑器，配置网址、文件夹、组件、主题、壁纸、图标、Dock 与摆放，不手工填写 JSON。页面必须持续显示“正在编辑官方预设”，与个人桌面明确隔离。

发布流程：保存草稿 → 校验引用/组件 → 桌面与移动端预览 → 发布不可变版本。当前生效版本通过单独指针切换；回滚是切换指针，不覆盖历史版本。

只有官方公共资源可以进入预设。使用管理员私人上传时必须先明确复制/提升为官方资源，不能泄露个人资产、账号 ID、访问令牌或私人网址。会员组件不能由预设无条件授予会员权益。

初始化优先级：已有此账号云端桌面 > 已有用户本地桌面 > 当前官方预设。空桌面可能是用户主动清空，判断初始化必须用显式状态，不能依赖“列表为空”。复制时生成用户自己的实例 ID，记录 preset_id/preset_version，不复制官方资源二进制。

管理员发布 V2 只影响之后首次初始化的新用户；老用户保持原状。用户可主动“恢复官方预设”，操作前必须生成可下载备份并确认；启用云同步时说明此重置会同步至其他设备。

## 9. P07 管理后台

首版模块：概览、用户、商店内容、预设桌面、系统配置、审计日志。支付开启后再展示订单/会员管理；积分能力交付后再显示其用量与发放状态。未上线不显示虚假统计卡片。无 Creator、分账、提现和面向投稿的审核中心。

管理员是受保护的平台角色，不是购买会员得到的权益。所有后台 API 在服务端检查真实身份与当前角色；隐藏菜单、前端变量和可编辑 user_metadata 都不是授权。

默认预设、商品发布、角色变更、账号封禁、删除及权益调整必须有操作记录。重大操作有二次确认；后台不得回显 ImgBed Token、网关高权限凭据或数据库高权限密钥。

ImgBed 的存储渠道、底层文件管理、索引和备份继续由现有官方 ImgBed 负责。DTab 后台保留用户归属、业务额度、错误状态与业务统计；不重写一套渠道后台。不同 MIME 的渠道选择只有在当前 ImgBed 部署支持并验证后才启用，不预设自动冷热迁移能力。

后续 New API 同理：模型、渠道与实际 AI 扣费留在网关；DTab 管订单、会员、积分包发放和用户展示，不维护第二套可写 AI 余额。不得将管理员手动填一个余额视为可靠充值。

## 11. 发布原则

完成文档不代表验收通过。桌面 beta、相册开放、商业收款、AI 积分消费和大型应用集成分别由功能开关控制；任何影响数据隔离/迁移的 P0 问题阻止相关功能公开发布。外部服务凭据与实际容量未验证时保持明确不可用状态，不能使用 mock 冒充生产。

本次新增收费合同不改变 05 文档原 M0–M5 的阶段顺序，不要求现在实现 New API、AI Studio、去水印或支付。不得为了兑现尚未验证的每日积分/无限算力宣传而提前收费。
