# DTab：个性化本地导航

当前主页面沿用原版 GoTab，不是重新设计的导航页。第一阶段先完成本地运行，再逐步整理原版模块，随后接入 Supabase 自动跨设备同步和浏览器扩展。

## 当前结构

- `legacy/gotab/web/`：原版 279 个发布文件，保留原样和许可证。
- `src/local/`：可维护的 TypeScript 本地接口、启动器、离线缓存及上传入口处理。
- `scripts/`：构建与静态预览工具。
- `docs/original-baseline.json`：原版文件 SHA-256 与构建改动清单。
- `experiments/redesign/`：之前新设计的实验版本，已退出主构建，保留备查。

这仍是**原版发布包 + 源码适配层**，不是已还原全部组件的源码工程。保留原版交互与数据模型；构建调整启动入口、站点配置及品牌文案，替换 Logo 和产品介绍面板。所有改动记录在构建清单中，原始发布文件仍保持不变。

## 本地运行

使用 Node.js 24 与 pnpm（仓库单一 lockfile 为 pnpm-lock.yaml）：

```sh
npm i -g pnpm@11.7.0
pnpm install
pnpm run build
pnpm run preview -- --port 4173
```

打开 http://127.0.0.1:4173/ 。预览进程只提供静态文件，不运行 Go 或业务 API。首次打开需要加载并缓存约 10 MB 原版资源，之后可断网重新打开。生产托管需 HTTPS，且当前构建部署在域名根路径。

```sh
pnpm test
pnpm run test:e2e
```

浏览器测试使用本机 Microsoft Edge。

## 数据与功能边界

- 保留原版页面、卡片编辑、设置、分组及原版备份格式。
- 收藏和设置沿用原版 Redux/localStorage 持久化；部分历史和壁纸数据使用 IndexedDB。没有换成新数据结构。
- 浏览器 Service Worker 在本地响应初始化 API，不依赖原 Go 后端。
- 清理站点数据会丢失本地收藏，请使用原版迁移备份。不同端口、域名、浏览器的数据互不共享。
- 上传图片入口隐藏，上传 API 明确返回未启用；备份文件导入保留。未接入图床。
- 网页“获取信息”目前仅提供域名及 `/favicon.ico` 候选地址，不代表已抓取网页标题或保证图标存在。开发版扩展已实现读取当前页面标题和图标，实际安装验收待完成。
- 账号与 Supabase 同步代码已接入，真实云端联调待完成；依赖原服务器的小组件/在线资源库尚未迁移，接口返回未启用或空列表，不伪造云端成功。
- 断网可操作本地收藏和设置；外部网站、外链图片及网络小组件不保证离线可用。

## DTab 品牌

品牌名、页面标题、Logo、标签页图标、默认卡片及备份文件名统一为 DTab。原产品官网、推广和群聊入口替换为本项目仓库、使用说明和问题反馈；不沿用原作者的收款码。许可证署名保持完整。

旧浏览器数据仅迁移能够识别的原版默认卡片与默认标题；用户自行创建或改名的收藏不做全局替换，兼容存储键不改名。迁移前备份保存在 `dtab:branding-backup:*` 本地存储键中。

## 独立默认模板

config/default-template.json 保存版本化的初始布局和卡片，不依属于管理员账号。启动器仅对新浏览器复制一次；发布新模板不会覆盖已有收藏。模板不包含账号或会话。完整上线进度见 docs/launch-checklist.md。

站点级名称与功能开关统一在 src/local/site-settings.ts 修改，构建输出的站点脚本与 API 使用同一份配置。管理员个人数据不参与生成。开发与 CI 使用 Node.js 24 + pnpm；EdgeOne 生产构建支持其预装 Node.js 22.11.0，安装命令为 npm i -g pnpm@11.7.0 && pnpm install --frozen-lockfile，构建命令为 pnpm run build:edge。
## Supabase 环境配置与账号入口

复制根目录 `.env.example` 为 `.env.local`，在本机填写 `VITE_SUPABASE_URL` 与 `VITE_SUPABASE_PUBLISHABLE_KEY`，再执行 `pnpm run build`。仅接受 `sb_publishable_` 公共密钥；数据库密码、Secret/service_role 密钥不要写入构建环境。该两项公共配置会进入前端构建产物，数据安全依赖登录身份与数据库 RLS。

原版侧边栏的“迁移备份”页已整合 Supabase SDK 的邮箱注册、登录和退出。未配置时保持本地模式并显示提示，原版导入、导出与迁移功能不受影响。同步传输层已对接查询与 RPC。首次登录后需明确选择“以本地数据启用同步”或“使用云端数据启用同步”；启用后编辑防抖上传、每 15 秒拉取，并在恢复联网后重试。界面显示冲突时停止上传，可导出双方队列备份并明确选择整份本地或云端版本。

目前登录/退出浏览器测试使用模拟 HTTP 服务；真实 Supabase 邮件、JWT、刷新会话与用户隔离仍待真实项目联调。

同步启用前会保存安全备份；退出后停止同步。在同一浏览器多个标签页中，目前只允许一个标签页持有同步锁，其他标签页会提示到同步标签页操作。真实 Supabase 双设备联调尚未完成。

在侧边栏“迁移备份”的同步区中可主动恢复当前部署版本的默认模板；恢复前保存可下载的原版 JSON 备份，确认框说明已启用同步时重置会同步到其他设备。GitHub 检查工作流已准备：构建、单元测试、数据库权限测试、Chromium 浏览器回归；代码已提交远端；当前 Actions 作业在执行步骤前失败，云端 CI 尚未通过。
